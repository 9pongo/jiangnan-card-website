# QA 專用工作階段交接

## 工作目標

以 [QA_CHECKLIST.md](QA_CHECKLIST.md) 驗收江南寶卡的本機前後端。不要實作帳號建立、SSO 實際供應商串接、金流、退款、發票、出貨或寄售款項結算；這些是明確保留範圍。

## 工作規則

1. 先確認 `docker compose ps` 中 `db` 與 `api` 均正常，並用 `http://localhost:3000/health` 驗證 API。
2. 用 `python -m http.server 4173` 提供靜態網站，驗收 `http://localhost:4173/` 與 `/admin/`；localhost 應顯示本機 API 已連線，GitHub Pages 必須保持展示模式。
3. 所有寫入流程都要用 API 回應與 PostgreSQL 查詢雙重驗證，特別是價格、庫存、訂單到期、Banner 素材及寄售狀態。
4. 每個缺陷都要寫出重現步驟、預期／實際結果、相關資料 ID 和風險等級。不得以原始碼閱讀替代行為驗證。
5. 桌面 1440 x 900 與手機 390 x 844 都要截圖驗證首頁、商品管理、內容管理、Banner 管理與寄售管理。檢查文字、按鈕、對話框與廣告版位是否重疊或溢位。
6. 不得宣稱金流、公司 SSO、雲端 S3/GCS、惡意檔掃描或正式帳號管理已完成。它們不在本機本輪驗收範圍。

## 必交付結果

- `QA_CHECKLIST.md` 每項的通過／失敗／未測狀態。
- 缺陷清單，依 P0、P1、P2 排序。
- 驗證命令與可重現資料 ID。
- 桌面與手機截圖證據。
- 明確的 Go／No-Go 結論，並將「本機可驗收」和「正式上線」分開陳述。
